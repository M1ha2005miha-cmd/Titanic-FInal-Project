# Titanic: предсказание выживания пассажиров

- Задача бинарной классификации
- Предсказания проводились на основании датасета с сайта Kaggle `Titanic` (891 пассажир в обучающей выборке и 418 в тестовой)
- Качество оценивается метрикой accuracy (доля правильных из всех)

**Выводы по результатам**
лучашя модель по кросс-валидации - LightGBM после подбора гиперпараметров (0.845), но на Kaggle она показала худший результат (0.756). Лучший результат на Kaggle (0.766) у логистической регрессии, и он сопал с правилом "все женищины выжили": ни одна модель не обогнала простеший baseline. 

Причины две. Датасет маленький, и сложные модели частично запомнили данные конкертных пассажиров вместо общих закономерностей. Кроме того, гиперпараметры подбирались и оценивались на одних и тех же фолдах: чем больше вариантов перебиралось, тем сильнее завышена оценка на кросс-валидации. Разница между моделями на Kaggle - около 4 пассажиров из 418, то есть в пределах шума.

## Подход

### Анализ данных (EDA)

Подробный анализ - в `notebooks/eda.ipynb`. Сильнее всего на выживание влияло пол, титул и класс билета: женщины и дети выживали значительно чаще взрослых мужчин, пассажиры 1-го класса - чаще, чем 3-го.

Пропуски были в столбцах Age, Cabin, Embarked и Fare (в тестовой выборке).
Возраст заполняется медианой по титулу, вместо номера каюты используется признаки наличия каюты, порт посадки и стоимость билета заполняются самым частым значением и медианой соответственно.

### Признаки 

| Признак | Зачем |
|---|---|
| `Title` | Титул из имени (Mr, Mrs, Miss, Master) даёт примерный возраст: `Master` — мальчики, которые выживали чаще взрослых мужчин |
| `FamilySize`, `FamilyGroup` | Размер семьи на борту: члены небольших семей выживали чаще одиночек и больших семей |
| `HasCabin` | Наличие номера каюты связано с дорогим билетом и высоким классом, а значит, с более высоким шансом выжить |
| log(`Fare`) | Логарифм сглаживает выбросы в стоимости билета, которые искажают линейные модели, KNN и нейросеть. На accuracy повлиял в пределах шума |

### Предобработка

Вся предобработка (заполнение пропусков, масштабирование числовых признаков, one-hot кодирование категориальных) собран в `Pipeline` вместе с моделью.
Так она обучается только на обучающих фолдах кросс-валидации, и информация из проверочного фолда не просачивается в обучение (защита от утечки данных).
Например, медиана возраста по титулу считается заново на каждом раунде CV.

### Валидация 

Стратифицированная 5-кратная кросс-валидация (`StratifiedKFold`): каждый фолд по очереди становится проверочным, а в каждом сохраняется исходная пропорция классов (62% погибших / 38% выживших).

Модели сравниваются по пяти метрикам. Одной accuracy недостаточно: модель, которая всем предсказывает "погиб", получает accuracy 0.616, не найдя ни одного выжившего. Поэтому дополнительно считаются precision, recall, f1 и ROC-AUC.

### Модели

| Группа | Модели |
|---|---|
| Baseline | Предсказание самого частого класса (0.616), правило «все женщины выжили» (0.787) |
| Классические | Логистическая регрессия, KNN, дерево решений, случайный лес |
| Бустинги | XGBoost, LightGBM |
| Нейросеть | PyTorch через обёртку skorch |
| Ансамбли | Мягкое голосование, стекинг |

**Подбор гиперпараметров.** `GridSearchCV` по accuracy на тех же фолдах CV
для трёх моделей — по одной каждого типа:

| Модель | Что подбиралось | Лучшее значение |
|---|---|---|
| Логистическая регрессия | `C` | 1 (значение по умолчанию) |
| Случайный лес | `max_depth`, `min_samples_leaf` | 6, 1 |
| LightGBM | `n_estimators`, `learning_rate`, `num_leaves` | 100, 0.1, 7 |

Оптимум `num_leaves=7` для LightGBM подтвержден расширением сетки в обе стороны: и более простые (3, 5), и более сложные (15, 31) деревья дали меньшую accuracy. На небольшом датасете выигрывают более простые модели.

**Нейросеть.** Один скрытый слой из 16 нейронов, ReLu, dropout 0.2, оптимизатор Adam, ранняя остановка по ошибке на отложенной части данных. Результаты (0.824) на уровне логистической регрессии: на 891 строке сети не хватает данных, чтобы найти закономерности сверх уже созданных признаков.

**Ансамбли.** Объединяют четыре модели разных типов: логистическую регрессию, KNN, настроенные лес и LightGBM. Голосование усредняет их вероятности, стекинг обучает логистическую регрессию взвешивать их ответы. Ни один ансамбль не превзошел лучшую одиночную модель: модели ошибаются на одних и тех же "трудных" пассажирах, и усреднение этого не исправляет.

## Технические сложности

| Проблема | Симптом | Решение |
|---|---|---|
| Конфликт OpenMP между PyTorch и LightGBM на macOS | `segmentation fault` при обучении LightGBM | Бустинги импортируются до PyTorch: первая загруженная библиотека «владеет» OpenMP |
| Взаимная блокировка потоков | Зависание при обучении нейросети | `torch.set_num_threads(1)`: для маленькой сети один поток не медленнее |
| Несовпадение типов в PyTorch | `Float can't be cast to Long` | Наследник обёртки skorch, приводящий метки к float перед расчётом ошибки |

Выводы: порядок импорта библиотек может влиять на работу программы, и это
нужно фиксировать в коде комментарием. Библиотеки строго ожидают
определённые типы данных: sklearn приводит их сам, PyTorch — нет.

## Что можно улучшить

- **Честная оценка при подборе гиперпараметров.** Вложенная кросс-валидация или отложенная выборка, которая не участвует в выборе модели. Сейчас подбор и оценка идут на одних фолдах, поэтому оценка CV завышена.
- **Новые признаки.** Палуба из первой буквы номера каюты; группы пассажиров с одинаковым номером билета (путишествовали вместе).
- **Другие модели.** CatBoost, который работает с категориальными признаками без one-hot кодирования, и SVM.(идея нейронки)
